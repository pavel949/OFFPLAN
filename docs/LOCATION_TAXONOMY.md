# Таксономия локаций и страновой модуль

## Иерархия

```
страна (jurisdiction, ISO 3166-1 alpha-2: TH, VN, KH)
  └─ регион / город-направление (regions.level = 'region'): Пхукет, Бангкок, Паттайя, Хуахин, Хошимин …
       └─ локация / район (regions.level = 'district'): Банг-Тао, Сукхумвит, Джомтьен, Мы Кхе …
            └─ (зарезервировано) квартал / area (regions.level = 'area')
```

- Источник данных в коде: `lib/geo-seed.ts`. Из него генерируется SQL (`scripts/gen-geo-migration.mjs`) и он же служит запасным вариантом, когда БД недоступна (разработка).
- В БД: `jurisdictions` (страна, валюта, языки, часовой пояс, `is_active`), `regions` (дерево, имена RU/EN/локальное), `legal_topics` (правила и юридическая информация страны).
- `slug` локации: латиница в нижнем регистре, уникальна внутри страны и на практике глобально (адрес `/locations/[slug]`). Для коллизий между странами добавляйте префикс города (`hcmc-district-1`).
- Проект хранит английское название локации в `zone`. Страница локации находится по `slugify(zone)`; поэтому `slug` района должен совпадать со slug его английского названия (тест `lib/geo-seed.test.ts`). Исключения: составные названия («Silom & Sathorn») с явным slug.

## Как добавить локацию

1. Внести район в `lib/geo-seed.ts` под нужным регионом (или создать регион).
2. `node --experimental-strip-types scripts/gen-geo-migration.mjs > supabase/migrations/<ts>_...sql` и применить миграцию (повторяемая, обновляет названия).
3. По желанию: описание в `lib/location-content.ts` (общие сведения, вычитка местным специалистом).
4. Застройщик или оператор выбирает локацию в мастере «Новый проект» (или вводит новую). Страница локации, счётчики, аналитика и поиск появляются автоматически после публикации проекта.

## Как открывается новая страна

Порядок виден на странице страны (`/countries/<slug>`, блок «Запуск страны»):

1. **Таксономия локаций**: города и районы заведены в справочник.
2. **Юридический обзор**: темы в `legal_topics` (ownership, process, taxes, disputes, visa …) со статусом.
3. **Чек-лист проверки**: страновой чек-лист документов в реестре.
4. **Первые застройщики**: проекты, цены, наличие.
5. **Открытие**: `jurisdictions.is_active = true`, статус «Работает».

## Правила и юридическая информация страны (`legal_topics`)

Жизненный цикл: `planned` → `draft` → `in_review` → `verified` → `outdated`.

- `verified` допустим только с указанием юриста (`reviewed_by`), даты проверки и срока действия (`valid_until`): ограничение в БД.
- Просроченная проверка отображается как «Требует обновления» (`effectiveStatus`).
- Сейчас ни одна тема не проверена юристом: все темы Таиланда и Вьетнама имеют статус «черновик» или «готовится». Статус на странице показан честно.
- Публичное чтение разрешено только для `is_published`; запись только сотрудникам (RLS), тесты `supabase/tests/70_legal_topics.sql`.

## Что ещё нужно для полностью мультистранового каталога

- Валюта проекта и таблица курсов: сейчас цены `pN` считаются в млн THB, поэтому аналитика смешивает валюты только после этой доработки.
- Таксономии (сегмент, пляж, владение, управление) по юрисдикциям через `taxonomy_terms` вместо общей для Таиланда.
- Страновые шаблоны проверки реестра (`verification_checklist_templates` по `jurisdiction_code`) и страновые версии разделов «Знания» и «Защита прав».
- Языковые версии (en, th, vi) названий и описаний.

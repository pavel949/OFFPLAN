Исправление: `20261104015922_harden_privileges.sql` (применена в prod), `20261104015929_fk_covering_indexes.sql` (применена), `20261104031823_drop_stale_policies.sql` (применена в prod 2026-11-04 по подтверждению владельца), тест `supabase/tests/50_privileges.sql` (имитирует права Supabase по умолчанию, проверяет, что публичные чтения работают, а запись и приватные таблицы закрыты).

- Миграция `20261104031923_project_sources_sync.sql` (применена в prod): у `project_sources` поля `sync_enabled`, `last_synced_at`, `last_sync_note`; включить синхронизацию может только команда IE (триггер), поэтому застройщик не может направить сервисный аккаунт на чужую папку.
- Доступ только на чтение через один сервисный аккаунт платформы. Застройщик делится папкой с e-mail сервисного аккаунта (роль «Читатель»), свои пароли и токены Google никому не передаёт.
- Читаются Google Таблицы (первый лист, экспорт в CSV) и CSV/TSV до 2 МБ. Файлы `.xlsx` пока не читаются: нужно открыть как Google Таблицу.
- Дальше всё как в обычном импорте: проверка без записи → «Применить»; лоты вне файла не удаляются; после применения источник отмечается как подтверждённый.
- **Настройка владельцем:** Google Cloud → создать проект → включить Google Drive API → Service Account → ключ JSON → вставить содержимое целиком в переменную `GOOGLE_SERVICE_ACCOUNT_JSON` (Vercel, тип Secret). Проверено только на моках: с реальным Drive сценарий ещё не прогонялся.
